# 长篇与中文叙事

2026-10-27，提示词版本 `studio-staged-v1.2.3`。

长篇是文字版的可选项。仍只生成一则故事，由模型根据场景需要选择8–16页；目标3200–5600字符，服务端接受2400–8000字符和16–64段。页数不代表固定纸张容量。长篇上游直接返回8–16个场景，每个场景2–4个自然段；程序按顺序生成段落编号与阅读页面，正文只在所属场景出现一次，后续解释仍按已生成的编号逐字引用。标准文字与漫画保留原来的段落引用结构。短故事不能靠切成更多页通过长篇校验。场景先分配约4000字符的全篇预算，重要转折多写、普通转场少写；超长修复允许压缩重复描写与对白。故事API只写小说正文，正式定义、“解”和“议”由后续API单独生成。

写作阶段先依据已保存知识构思人物目标、阻力、选择和后果；场景承担新的行动、信息或关系变化。对白区分人物的打算与语气，叙事保持视角和信息边界，重要转折充分展开、平常时间适度概述。避免在具体动作之后重复贴情绪标签、堆叠比喻或逐段总结寓意。简短原创节奏样例只示范写法，提示禁止复用其情节。

自然语言调整不覆盖正式定义、数量、人物身份、关系条件和证据边界。概念名称与正式解释留在“解”，讨论与新情境应用仍在“议”。已有审核/断点机制复用，不为了文风增加额外模型轮次；文风指引不能当作学术准确或教学效果证明。

参考与边界：

- [DeepSeek官方温度说明](https://api-docs.deepseek.com/quick_start/parameter_settings/)将创意写作列为可提高随机性的场景。这是通用参数建议，不保证ECNU路由的底层版本或成文质量；本次不盲目改变全局温度、并发和重试次数。
- [NovelNovel作者公开的叙事方法](https://github.com/wanrenhuifu/NovelNovel/blob/master/skills/novel-prose/SKILL.md)与[对白方法](https://github.com/wanrenhuifu/NovelNovel/blob/master/skills/novel-dialogue/SKILL.md)作为工程写作经验参考，涉及视角一致、句式节奏、动作与对白。它们不是教学研究证据；本项目未安装或执行该仓库的代码。
- 本地“说人话”与humanizer-zh用来提炼去模板规则；不以词语黑名单替代情节设计，也不虚构细节或修改学理来追求口语感。

标准文字及漫画保持原有页数；原有案例不重写。长篇禁止新建或切换为漫画，避免16页暗中触发生图调用。没有实际受试者数据，不宣称长篇提升了学习效果。
